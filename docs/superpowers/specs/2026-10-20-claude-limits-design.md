# claude-limits — дизайн

Дата: 2026-10-20

## Цель

Видеть расход 5-часового и недельного лимита подписки Claude в двух местах:

1. в строке статуса Claude Code;
2. в строке меню macOS.

Весь код свой. Без сторонних расширений, без сети, без токенов и cookie.

## Источник данных

Claude Code передаёт скрипту строки статуса JSON на stdin. В нём есть поля
(см. https://code.claude.com/docs/en/statusline):

- `rate_limits.five_hour.used_percentage`, `rate_limits.seven_day.used_percentage` — 0–100;
- `rate_limits.five_hour.resets_at`, `rate_limits.seven_day.resets_at` — Unix-время сброса в секундах.

`rate_limits` есть только у подписчиков Pro/Max и только после первого ответа в сессии.
Каждое окно может отсутствовать независимо. Окно пропадает, когда его `resets_at` прошёл.

Это единственный источник данных. `~/.claude/.credentials.json`, недокументированные
эндпоинты и cookie claude.ai не используются.

## Общие правила

- Длина окна: 5 часов = 18000 с, неделя = 604800 с.
- Процент ограничивается диапазоном 0–100 для отрисовки. Исходное значение ≥ 100 означает «исчерпан».
- Цвет по проценту `u`: `u < 60` зелёный, `60 ≤ u < 85` жёлтый, `u ≥ 85` красный.
- Формат времени до сброса `d = resets_at − now`:
  - `d ≤ 0` — окно считается сброшенным;
  - `d < 1ч` — `45м`;
  - `d < 24ч` — `2ч10м`;
  - иначе — `4д3ч`.
- Прогноз исчерпания:
  - начало окна `s = resets_at − L`, прошло `e = now − s`;
  - прогноз считается, только если `e ≥ 600` с и `0 < u < 100`;
  - момент исчерпания `t_end = now + (100 − u) · e / u`;
  - прогноз показывается, только если `t_end < resets_at`.

## 1. Строка статуса (вариант S4)

Вид:

```
5ч ████▏····· 42% 2ч10м   нед █▊········ 18% 4д3ч
```

- Полоса из 10 ячеек с точностью до 1/8 ячейки: `n = round(u / 100 · 80)` восьмых долей,
  `n / 8` полных `█`, остаток от 1 до 7 рисуется символом из `▏▎▍▌▋▊▉`,
  оставшиеся ячейки — приглушённые `·`.
- Полоса и процент окрашены по порогам. Время до сброса приглушено.
- Окно, которого нет во входных данных или чей `resets_at` прошёл, не выводится.
- Нет ни одного окна — выводится приглушённое `лимиты: —`.
- В строке только лимиты. Модель, папка и git не выводятся.
- Реализация: `statusline/statusline-limits.sh`, bash + `jq`, читает только stdin, без сети.
- Конфигурация Claude Code (`~/.claude/settings.json`):

  ```json
  "statusLine": {
    "type": "command",
    "command": "~/.claude/statusline-limits.sh",
    "refreshInterval": 60
  }
  ```

## 2. Передача данных в строку меню

- Если во входных данных есть хотя бы одно окно, скрипт записывает `~/.claude/limits.json`:

  ```json
  {
    "updated_at": 1760958000,
    "five_hour": { "used_percentage": 42.0, "resets_at": 1760965200 },
    "seven_day": { "used_percentage": 18.0, "resets_at": 1761318000 }
  }
  ```

  Отсутствующее окно в файл не пишется.
- Запись атомарная: временный файл в той же папке, затем `mv`.
- Если окон нет, файл не трогается, чтобы не затереть последние значения.
- Скрипт пишет файл, только когда окна его сессии (`session_id`) изменились с прошлой записи.
  Последняя запись сессии хранится в `${TMPDIR}/claude-limits/<session_id>`. Claude Code
  перезапускает скрипт раз в минуту со старыми цифрами, и простаивающая сессия не должна
  затирать более свежие данные другой сессии или мода.

## 3. Приложение в строке меню (вариант R2)

- Swift + AppKit, без Xcode-проекта и зависимостей. Сборка через `swiftc` в
  `~/Applications/ClaudeLimits.app`. `LSUIElement = true`, значка в Dock нет.
- Код разделён на две части:
  - `LimitsCore.swift` — чистая логика: разбор файла, цвета, формат времени, прогноз, состояния;
  - `App.swift` — AppKit: значок, меню, таймер.
- **Значок:** два кольца диаметром ~18 px с числом внутри, слева 5 часов, справа неделя.
  Цвет кольца следует порогам. Цифры рисуются `labelColor`, поэтому подстраиваются
  под светлую и тёмную строку меню.
- **Состояния кольца:**

  | Состояние | Кольцо | Число |
  |---|---|---|
  | норма | заполнено на `u`, цвет по порогу | `u`, округлённое |
  | `u ≥ 100` | полное, красное | `!` |
  | `updated_at` старше 30 мин | заполнено на `u`, серое | `u` |
  | `resets_at` прошёл или окна нет в файле | пустое | `–` |
  | файла нет или он не читается | пустое серое | `–` |

- **Меню по клику:**

  ```
  ● 5 часов: 62% · сброс в 16:15
      в таком темпе кончится ~15:40
  ● Неделя: 18% · сброс в пт 17:00
  ───────────
  обновлено 2 мин назад
  Выход
  ```

  Строка прогноза появляется по правилу из раздела «Общие правила».
  Время сброса показывается как время суток, если сброс сегодня, иначе с днём недели.
- Файл перечитывается раз в 30 с и при каждом открытии меню.
- **Автозапуск:** LaunchAgent `~/Library/LaunchAgents/com.flydge.claude-limits.plist`.
  Устанавливается только после отдельного подтверждения пользователя.

## 4. Мод для приложения Claude (вариант D3)

Вкладка Code приложения Claude не рисует `statusLine`, поэтому там лимиты показывает мод
`limit-rings` (папка `mod/limit-rings/`). Имена с префиксом `claude-` зарезервированы.

- **Данные:** `$.session.usage().rateLimits` при старте сессии и `session.measure` после
  каждого ответа. Поля: `kind` (`five_hour`, `seven_day`), `percentUsed`, `resetsAt` (ISO).
- **Где:** `ui.render` на `AbovePrompt`, только для `e.surface === 'desktop'`. В терминале
  полоса не рисуется.
- **Вид:** два SVG-кольца 20×20 с числом внутри, по тем же порогам и состояниям, что R2.
  Рядом `5 часов · сброс 16:15` и `Неделя · сброс пт 17:00`. Прогноз (по правилу из «Общих
  правил») выводится цветом `warning`: `· кончится ~15:40`.
- **Файл:** только по `session.measure` мод записывает `~/.claude/limits.json` в формате
  раздела 2. При старте сессии не пишет: у возобновлённой сессии цифры могут быть старыми.
- Раз в минуту перерисовывается, чтобы прошедший сброс и прогноз были актуальны.
- Установка: маркетплейс `flydge/claude-limits` (`.claude-plugin/marketplace.json`).

## Установка

`install.sh` только копирует файлы:

- скрипт строки статуса в `~/.claude/statusline-limits.sh`;
- собранное приложение в `~/Applications/ClaudeLimits.app`.

Изменение `~/.claude/settings.json` и установка LaunchAgent делаются отдельно,
после того как пользователь увидит diff и подтвердит его.

## Проверка

- **Скрипт строки статуса:** тесты на фикстурах JSON в `statusline/test/`:
  - оба окна;
  - только одно окно;
  - пустой ввод и ввод без `rate_limits`;
  - 0 %, 100 %, больше 100 %;
  - прошедший `resets_at`.

  Проверяется и вывод (без цветовых кодов), и содержимое `limits.json`.
  Текущее время подставляется через переменную окружения, чтобы тесты были детерминированными.
- **Логика Swift:** тестовый исполняемый файл `menubar/Tests/main.swift` собирается вместе
  с `LimitsCore.swift` и проверяет пороги, формат времени, прогноз и состояния.
- **Значок:** проверяется скриншотом строки меню.
- **Claude Desktop:** проверить, запускается ли строка статуса во вкладке Code приложения Claude
  или только в терминальном `claude`, и сообщить результат пользователю.
