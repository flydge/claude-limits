# 001. Колокольчик: сессии, которые ждут ответа

**Статус:** сделано 28.10.2026
**Ветка:** `feat/attention-bell`
**Задачи:** `001-attention-bell.tasks.md`

## 1. Одно предложение

Когда сессия в приложении Claude ждёт ответа (нужно разрешение, Claude задал вопрос, задача
готова), в строке меню macOS появляется колокольчик с числом, а над полем ввода в других
сессиях — её строка в списке «N ждут ответа». Нажатие на любой из них открывает эту сессию. Если сессия
ждёт дольше 5 минут, приходит одно напоминание.

## 2. Вход → выход

| | что | формат |
|---|---|---|
| вход | события сессии в моде `limit-rings` | `classic.PermissionRequest`, `tool.call` (AskUserQuestion, ExitPlanMode), `turn.complete`, `prompt.submit`, `session.end` |
| вход | файлы сессий приложения Claude | `~/Library/Application Support/Claude/claude-code-sessions/*/*/local_*.json`, только для чтения: `sessionId`, `cliSessionId`, `title`, `isArchived`, `lastFocusedAt` (мс) |
| выход | состояние одной сессии (пишет мод) | `~/.claude/attention/<cliSessionId>.json` |
| выход | общий список (пишет приложение в строке меню) | `~/.claude/attention.json` |
| выход | колокольчик, его меню и напоминание | `NSStatusItem` в `ClaudeLimits.app`, `UNUserNotification` |
| выход | список над полем ввода | заголовок и строки в полосе `AbovePrompt` мода `limit-rings` |

**Новый файл `~/.claude/attention/<cliSessionId>.json`** (пишется атомарно):

```json
{"session_id": "<cliSessionId>", "state": "working|permission|question|decision|done|ended", "since": <epoch s>}
```

Переходы. Начало и конец хода учитываются только в основной переписке (ход субагента
кончается внутри основного); запрос разрешения и вопрос — из любой, потому что держат человека:

| событие | новое состояние |
|---|---|
| `prompt.submit`, `turn.start` | `working`; метка «ждёт решения» снимается |
| `classic.PermissionRequest` (запрос разрешения у человека) | `permission`; для `AskUserQuestion` и `ExitPlanMode` — `question` |
| `tool.call` для `AskUserQuestion` или `ExitPlanMode`, до `next` | `question` |
| `tool.call` для `mcp__ccd_session__start_session` с `initiation: "offer"` (вызов ждёт ответа человека), до `next` | `question` |
| `tool.call` для `mcp__ccd_turn__wrap_up` с непустым `ask`, непустыми `actions` или `blocked: true`; `tool.call` для `mcp__ccd_session__start_session` с `initiation: "own_initiative"` (карточка задачи) | состояние не меняется, ход помечается «ждёт решения» |
| завершение `tool.call` (инструмент отработал или отказ), если было `permission` или `question` | `working` |
| `turn.complete` с причиной `answer`, `refusal` или `error` | `decision`, если ход помечен «ждёт решения», иначе `done`; метка снимается |
| `turn.complete` с причиной `aborted` (человек сам прервал) | `working`, то есть не показывать |
| `session.end` | `ended`: в API мода нет удаления файлов, такой файл удаляет приложение в строке меню |

`since` меняется только при смене состояния.

**Новый файл `~/.claude/attention.json`**: каждые 2 с его пишет приложение в строке меню, а
`ClaudeLimits --attention-json` печатает то же самое:

```json
{"updated_at": <epoch s>, "sessions": [
  {"id": "local_…", "cli_id": "…", "title": "…", "state": "permission|question|decision|done",
   "since": <epoch s>, "link": "claude://claude.ai/epitaxy/local_…"}
]}
```

Правила списка (Swift, `AttentionCore.swift`):
- Сессия попадает в список, если её состояние `permission`, `question`, `decision` или `done`, у неё есть
  файл в приложении Claude (сопоставление по `cliSessionId`) и `isArchived` у неё не `true`.
  Сессии терминала файла в приложении не имеют, поэтому в список не попадают.
- `done` считается просмотренным и пропадает, если `lastFocusedAt` позже `since`, или если эта
  сессия открыта прямо сейчас (у неё самый поздний `lastFocusedAt`), а Claude — активное
  приложение (`frontmostApplication` = `com.anthropic.claudefordesktop`).
- Порядок: сначала оранжевые — `permission`, `question` и `decision`, потом `done`; внутри группы — кто ждёт дольше,
  тот выше.
- Файлы приложения перечитываются только для сессий из списка; полный обход папки — только
  когда встретился незнакомый `cliSessionId`.

Прежние данные (`limits.json`, `system.json`) не меняются.

## 3. Сценарий

```
bash menubar/build.sh && build/ClaudeLimits.app/Contents/MacOS/ClaudeLimits --attention
```

Печатает список ожидающих сессий: значок состояния, название, сколько минут ждёт. Если никто
не ждёт — пустая строка.

Вживую, в приложении Claude с модом, поставленным из этой ветки:
1. В сессии X попросить Claude выполнить команду, на которую нужно разрешение, и переключиться
   в сессию Y.
2. В строке меню появляется колокольчик с «1». В его меню: «🔒 X · разрешение · 0 мин».
   Над полем ввода в Y — «1 ждёт ответа» и под ним строка X с оранжевой точкой.
3. Нажатие на название X в Y или на строку меню открывает X.
4. После ответа X работает дальше. Когда ход заканчивается, X переходит в «готово» (зелёная
   галочка), а когда вы открываете X, отметка пропадает. Колокольчик исчезает, если больше
   никто не ждёт.

## 5. Вне объёма

- Сессии в терминале: состояние мод записывает, но в список они не попадают, а переход к
  вкладке терминала не делается.
- Ответ на запрос разрешения или вопрос прямо из строки меню (как в Vibe Notch).
- Боковая панель, подпись под полем ввода, всплывающие сообщения внутри Claude (варианты B, C, D).
- Изменение собственных уведомлений приложения Claude и их стиля в macOS.
- Облачные сессии и Remote Control.

## 6. Материал для проверки

- Логика: фиктивные файлы сессий приложения и состояния в тестах (`menubar/Tests`, тесты мода);
  время подставляется, поэтому 5 минут не ждём.
- Вживую: приложение Claude на этом Mac (168 файлов сессий, `lastFocusedAt` обновляется при
  переключении — проверено). Ссылка `claude://claude.ai/epitaxy/local_…` взята из инструментов
  самого приложения.
- Мод ставится из GitHub (`flydge/claude-limits`). Для живой проверки нужен мод из этой
  ветки: на время проверки маркетплейс `flydge` переключается на локальную папку
  `~/claude-limits`, после проверки возвращается на GitHub. Новый мод подхватывают только
  новые сессии, поэтому живые проверки идут в двух свежих сессиях.

## 7. Кто решает

Детерминированно: переходы состояний (мод), сборка списка, «просмотрено», порядок, цвет значка,
момент напоминания (Swift). Мод только пишет состояние и рисует то, что лежит в
`attention.json`, как сейчас с `system.json`.

Суждением: как выглядят список и меню — смотрит пользователь на живой проверке. На десктопе
`Button` рисуется серой системной кнопкой, а ссылка — только с адресом `https:`, поэтому
названия — ссылки Markdown на `https://limit-rings.invalid/…`, которые отвечает сам мод. По той
же причине строка памяти и диска — текст, а «Подробнее» — такая же ссылка (просьба 28.10).

Порядок: сначала проверка, что `classic.PermissionRequest` вообще приходит в моде в сессии
приложения (задача 1) — от этого зависит способ ловить запрос разрешения. Swift-часть и мод
независимы по файлам (`menubar/` против `mod/`), договор между ними — формат файлов из
раздела 2.

## 8. Риски и деградация

- **`classic.PermissionRequest` в сессиях приложения приходит** (проверено зондом 28.10:
  Bash в режиме `default`, `AskUserQuestion`). Он приходит и тогда, когда приложение само
  одобряет вызов без человека; такое `permission` длится доли секунды и сменяется `working` по
  окончании `tool.call`. `tool.check` с `ask` не годится: в режимах `auto` и `bypassPermissions`
  он тоже `ask`, а решает не человек.
- **Формат файлов приложения Claude изменится.** Файлы без нужных полей пропускаются, и список
  пустеет. Приложение и мод не падают, кольца лимитов и памяти работают как раньше.
- **Приложение в строке меню не запущено.** Мод, как с `system.json`, сам вызывает
  `ClaudeLimits --attention-json`, если файл старше 10 с, и только в сессиях приложения.
- **Ошибка в хуке мода.** Хук вызывает `next` и ловит свои ошибки: инструменты и ходы никогда
  не блокируются из-за колокольчика.
- **Сессия закрылась без `session.end`** (приложение упало). Её файл остаётся, но если у
  сессии нет файла приложения или она в архиве, в список она не попадает. Состояние `working`
  в любом случае не показывается.

**Потолок:** одна рабочая сессия. Если за неё живые критерии 5–7 не сходятся — стоп и отчёт.
